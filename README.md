# 荣耀祈愿 · 在线抽奖系统

王者荣耀风格的祈愿抽奖站：深色星空 + 水晶聚光 + 光柱揭示 + 稀有度粒子爆发，支持后台随时改奖品、改概率、审核充值为代币。

## 快速开始

```bash
npm install
npm start
```

- 前台抽奖：<http://localhost:3000/>
- 管理后台：<http://localhost:3000/admin>
- 默认后台密码：**admin888**（登录后请立刻在「规则与外观」里改掉）

如果 3000 端口被占用：`PORT=3111 npm start`

## 目录结构

```
server.js            服务端（express，仅此一个依赖）
lib/db.js            JSON 持久化（写 data/db.json，带临时文件 rename + 节流落盘）
lib/lottery.js       抽奖核心：加权随机 / 库存 / 保底 / 五连
lib/seed.js          默认数据：稀有度、12 个默认奖品、默认规则
public/
  index.html         抽奖前台
  admin.html         管理后台
  css/               样式
  js/icons.js        手绘 SVG 图标库（离线可用，无外链素材）
  js/fx.js           Canvas 粒子 + WebAudio 合成音效（无音频文件）
  js/app.js          前台逻辑
  js/admin.js        后台逻辑
scripts/smoke.js     接口冒烟测试：node scripts/smoke.js
data/db.json         运行后自动生成，所有业务数据
```

## 抽奖规则（后台均可改）

| 项目 | 默认值 | 说明 |
| --- | --- | --- |
| 兑换比例 | 1 元 = 10 祈愿币 | 用户微信转账后发放 |
| 单抽 | 100 祈愿币 = ¥10 | |
| 五连抽 | 500 祈愿币 = ¥50 | 可另设优惠代币数 |
| 传说保底 | 60 抽必出 SSR 及以上 | 出 SSR/UR 后清零 |
| 荣耀保底 | 360 抽必出 UR | 出 UR 后清零 |
| 五连保底 | 必出 SR 及以上 | 五张全是普通/稀有时自动升级一张 |
| 库存 | -1 不限量 / 0 下架 | 抽完自动退出抽取，概率实时重算 |

默认奖池 12 项（总权重 9000）：荣耀水晶 0.167% / 传说 SSR 1.17% / 史诗 SR 8.9% / 稀有 R 27.8% / 普通 N 62%。

## 充值流程（无法自动收款，需你确认）

1. 用户在前台点「充值」，看到你的微信收款码 + 自己的邀请码（账号 ID）
2. 用户微信转账，备注里填邀请码，可选上传转账截图
3. 后台「充值审核」出现待处理订单，核对金额与备注一致后点「放行」
4. 代币按 1:10 实时发放到用户账户，前台 6 秒内自动刷新余额并提示

收款码在后台「规则与外观」上传；也可以只填微信号让对方搜索转账。

## 后台能改什么

- **奖池与概率**：增删奖品、改名称描述、改稀有度、改权重、改库存、换图标；带「概率助手」——直接填每个稀有度的目标百分比，自动反算权重
- **规则与外观**：站名、公告、代币名、兑换比例、单抽/五连价格、保底阈值、五连保底开关、维护模式、是否公示概率
- **充值审核**：放行 / 驳回 / 查看转账截图
- **用户管理**：手动发币扣币、重置保底、封禁账号
- **抽卡记录 / 操作日志 / 数据导出**
- **导出备份**：右上角「导出数据」下载完整 db.json

## 线上部署注意

数据写在服务器本地 `data/db.json` 和 `public/uploads/`，容器重启或被回收时会丢失，请定期用「导出数据」备份。若要长期稳定，建议把这两个目录挂到持久化存储上。

## 安全提醒

- 后台密码默认 admin888，**上线第一件事就是改掉**
- 每个用户在本地保存了一段身份签名，伪造他人 uid 会被服务端拒绝
- 服务端有 250ms 防连点节流，禁止同一账号瞬时刷抽奖
- 抽奖数据（用户、余额、库存、订单）全部在服务端，改前端页面改不了余额
